# AstrBot 短期共享情绪

让智能体拥有一份跨私聊、群聊和人格联动的短期心境。一个会话中的赞赏、亲近、冲突或安慰，会影响它接下来在其他会话里的语气、耐心、主动性和对话意愿。

支持开心、亲近、失落、生气、不安、疲惫、好奇以及平稳状态。多种情绪可同时存在，每轮展示最强的三种。主导情绪足够强时，还可以短暂婉拒适合暂停的话题。

## 工作方式

1. 在当前对话 LLM 请求准备完成后，读取已生效的人格主提示词、最近六条文字上下文和当前输入。图片评估开启时，附带当前请求的前两张图片。
2. 通过 AstrBot 已配置的模型评估本轮对智能体的情绪刺激。每轮至多增加或缓和每种情绪 0.35，乘以敏感度，最终强度限制在 0 到 1。低于 0.6 的置信度按零刺激处理。
3. 首次遇到某份主提示词时，在同一次评估中自动生成平稳和七种情绪各自的表达微调提示。缓存按完整主提示词、评估 Provider 和请求模型标识计算，主提示词变化后重新生成。缓存保存七天，最多一百份。
4. 将当前情绪强度与相应表达提示作为临时 `TextPart(...).mark_as_temp()` 加到 `extra_user_content_parts`。最终回复继续通过 AstrBot 和其他插件的正常流程生成。

所有会话共享同一个 SQLite 状态。不同人格会用各自的措辞表达同一份心境。并发请求的情绪评估与更新由一把异步锁串行处理，保证跨会话更新有一致的顺序。锁内包含一次模型评估，因此高并发下请求会排队。

评估输入保留完整主提示词，历史每条最多取末尾 800 字符，当前输入最多取末尾 10000 字符。主动聊天读取共享心境，主动发言内部指令产生的情绪增量固定为零。已缓存人格表达时，主动聊天直接复用缓存。

主提示词通常通过 AstrBot 的 `_trace_persona_id` 和人格管理器读取。WebChat 默认人格使用 AstrBot 的默认主提示词。第三方 Runner 未提供人格标识时，使用本次请求的 `system_prompt` 作为生成依据。

## 自动恢复

默认半衰期为 300 秒，同一种情绪最后一次明显刺激后最多持续 1200 秒。强度低于 0.04 时恢复平稳。每种情绪独立记录刺激时间，普通聊天和安慰会继续衰减，新的明显同类刺激会重新计时。

时间按墙上时钟计算，读取或使用情绪时按已经过去的时间恢复。关闭 AstrBot 的时间也计入，重启会继续恢复。没有新消息时无需运行后台定时器。回复中会持续给出当前心境，使旧回复里残留的情绪表述随新状态恢复。

## 情绪性婉拒

默认开启。主导情绪为失落、生气、不安或疲惫，强度至少 0.65，且评估模型判断当前话题适合暂停时，才进入婉拒抽样。实际概率为 `refusal_probability × 主导强度`，默认强度 0.8 时为 24%。

冷却默认 180 秒，所有会话共享。连续两个经过情绪处理的对话请求最多允许一次情绪性婉拒。认真求助、紧急困难、工作承诺、工具操作和文件分析会在评估提示中要求排除。最终是否婉拒及具体措辞仍由聊天模型结合主提示词决定，因此属于模型尽力执行的行为。

## 安装

要求 Python 3.11+、AstrBot `>=4.29.4,<5`，使用 AstrBot 内置的模型 Provider SDK，额外依赖为零。

在 AstrBot 插件管理中通过仓库地址安装。

```text
https://github.com/1972124398/astrbot_plugin_short_term_mood
```

也可以在 AstrBot 根目录运行以下命令，然后在插件管理中重新扫描或重启 AstrBot。

```shell
git clone https://github.com/1972124398/astrbot_plugin_short_term_mood data/plugins/astrbot_plugin_short_term_mood
```

安装后在插件配置中调整参数。`analysis_provider_id` 留空使用当前会话的模型，可填独立的小模型以降低等待和费用。默认图片评估开启，请为它配置支持视觉的模型。每次普通对话额外产生一次模型调用，首次生成人格情绪表达会消耗更多输出 token。评估默认超时 15 秒，可按服务延迟调整。

评估失败或输出无效时，本轮使用通用的角色情绪表达，已有情绪继续恢复，30 秒后再尝试评估。配置中关闭 `enabled` 可暂停整个插件，关闭 `enable_refusal` 可保留情绪表达并停止情绪性婉拒。

## 命令

| 命令 | 权限 | 效果 |
| --- | --- | --- |
| `/mood` | 所有人 | 查看智能体当前共享心境 |
| `/mood_reset` | 管理员 | 将全部会话共享的心境恢复平稳 |
| `/mood_set anger 0.8` | 管理员 | 设置共享情绪以调试，也可使用中文情绪名 |
| `/mood_refresh` | 管理员 | 清除人格情绪表达缓存，下轮重新生成 |

`mood_set` 接受 `joy`、`affection`、`sadness`、`anger`、`anxiety`、`fatigue`、`curiosity`，强度范围 0.04 到 1。设置会替换全部现有情绪，随后按时间恢复。

## 插件兼容

LLM 请求钩子优先级为 `-100`，在本机检查的记忆注入 `40`、默认钩子 `0` 和微信表情提示 `-50` 之后运行。兼容设计通过追加临时内容实现，原请求中的工具集合、图片、音频、用户输入、历史上下文和系统提示均交给现有流程管理。情绪评估使用 `Context.llm_generate()` 直接调用 Provider，因此不会递归进入对话钩子。评估调用使用自己的提示和输入，工具执行仍由主对话负责。

| 已检查的插件 | 版本 | 集成方式及范围 |
| --- | --- | --- |
| Codex Bridge | 1.2.0 | 保留已有工具授权与工具集合，`/codex` 等命令按前缀跳过 |
| 微信原生表情转图片 | 0.2.2 | 读取已转换图片，后置追加情绪临时内容 |
| Angel Memory | 3.1.0 | 在记忆注入后追加情绪，不调用记忆写入接口 |
| Reply Merge | 1.5.0 | 在合并请求之后评估，使用合并后的当前输入 |
| WeChat Native | 0.3.21 | 保留微信工具权限、PDF 内容和现有消息处理 |
| Proactive Chat | 1.3.0-beta.2 | 已检查其主动消息流程会派发标准 LLM 请求钩子，正常主动聊天会使用共享情绪 |

以上版本来自开发环境的源码接口检查，具体验证记录见下方。未来插件若覆盖整个内容列表，或自定义 Runner 绕过 `on_llm_request`，需要在对应集成点适配。其他插件可在事件中设置 `event.set_extra("short_term_mood_skip", True)`，让特定后台请求跳过情绪处理。

临时情绪提示会从 AstrBot 持久化的对话内容中排除。实际生成的回复仍可能被记忆插件观察并保存，长期记忆策略由记忆插件自己的配置决定。

## 数据与开发

运行数据位于 `data/plugin_data/astrbot_plugin_short_term_mood/mood.sqlite3`，存储一份共享情绪和人格表达缓存。评估输入包含主提示词、最近对话和当前内容，会发送给所选的模型服务。插件自身的数据库仅保存情绪数值、时间、拒答标记以及生成人格表达，日志只记录失败类型。

在仓库根目录运行核心回归验证。

```shell
python -m unittest discover -s tests -v
```

在能导入 AstrBot SDK 的 Python 环境中，同一命令还会运行真实 `ProviderRequest` 和 `TextPart` 的钩子集成验证。

开发时在 AstrBot 4.29.4 SDK 环境验证了跨会话与跨人格联动、并发更新、临时内容追加、命令跳过、恢复、人格缓存与主动聊天接入。还调用部署环境已配置的 `deepseek-v4.1-flash`，验证赞赏、攻击、道歉三种输入能生成有效情绪评估和八份人格表达提示，实测单次约 1.6 到 5.6 秒。模型测试使用独立调用，运行中的情绪状态由实际安装后的插件维护。
