# AstrBot 短期共享情绪

让智能体拥有一份跨私聊、群聊和人格联动的短期心境。一个会话中的赞赏、亲近、冲突或安慰，会影响它接下来在其他会话里的语气、耐心、主动性和对话意愿。

支持开心、亲近、失落、生气、不安、疲惫、好奇以及平稳状态。多种情绪可同时存在，每轮展示最强的三种。主导情绪足够强时，还可以短暂婉拒适合暂停的话题。

## 工作方式

1. 当前请求准备完成后，前台立即读取内存中的共享心境与已缓存的人格表达，将它们作为临时 `TextPart(...).mark_as_temp()` 加到 `extra_user_content_parts`，随后继续正常生成回复。
2. 同时保存当前主提示词、最近六条文字上下文、当前输入和图片引用的快照，放入后台检测队列。前台钩子没有网络等待，也无需等待后台的模型调用或数据库写入。
3. 单个后台任务按队列顺序评估本轮对智能体的刺激。每种情绪增量最多为 ±0.35，再乘敏感度，最终强度限制在 0 到 1。置信度低于 0.6 时按零刺激处理。
4. 首次遇到某份主提示词时，在后台同一次调用中自动生成平稳和七种情绪各自的表达微调提示。结果写入共享内存，从下一次读取状态的回复开始生效。首次生成完成前使用通用的角色表达提示。

所有会话共享同一个情绪状态，数据库保存状态以支持重启恢复。不同人格会用各自的措辞表达这份心境。数据库持久化在后台线程串行进行，前台使用内存中的状态。后台返回的结果会影响后续回复，一次已经开始生成的回复使用它开始时的情绪快照。

后台队列默认最多保留 16 个待处理请求，满时淘汰最早的待处理项。从入队到检测完成最长有效时间默认 120 秒，过期结果会丢弃。手动设置或重置情绪、清理表达缓存时，正在检测的旧结果和待处理项都会失效。卸载或重载会取消检测任务并保存当前状态。

评估输入保留完整主提示词，历史每条最多取末尾 800 字符，当前输入最多取末尾 10000 字符。主动聊天读取共享心境，主动发言内部指令产生的情绪增量固定为零。已缓存人格表达时，主动聊天直接复用缓存。

主提示词通常通过 AstrBot 的 `_trace_persona_id` 和人格管理器读取。WebChat 默认人格使用 AstrBot 的默认主提示词。第三方 Runner 未提供人格标识时，使用本次请求的 `system_prompt` 作为生成依据。

## 自动恢复

默认开启“持续对话时保持情绪”。所有真实对话共享活动计时，相邻互动不超过 300 秒时暂停情绪的自然衰减和恢复期限累计。安慰、冲突、赞赏等新互动仍能在后台改变情绪，持续聊天中也能从生气转为平静或开心。

最后一次真实互动后，超过配置的空闲时长就进入自然恢复。默认每 300 秒强度减半，累计自然恢复 1200 秒后归于平稳。强度低于 0.04 时也会归于平稳。明显同类刺激重置该情绪的恢复累计。主动聊天和 `/mood` 等命令会读取情绪，活动计时由真实对话推进。

关闭“持续对话时保持情绪”后，会按实际经过时间持续恢复。离线时间计入恢复，重启后接着计算。读取状态时根据时间计算自然恢复，无消息时无需额外定时任务。升级时会读取 0.1.0 的已有状态，配置中已有的数值也会保留。

## 情绪性婉拒

默认开启。主导情绪为失落、生气、不安或疲惫，强度至少 0.65 时抽样生成有条件的婉拒提示。实际概率为 `refusal_probability × 主导强度`，默认强度 0.8 时为 24%。

冷却默认 180 秒，所有会话共享。连续两个经过情绪处理的对话请求最多提供一次婉拒机会。最终聊天模型依据当前请求判断适用条件，认真求助、紧急困难、工作承诺、工具操作和文件分析要求照常处理。后台检测仅更新情绪，当前请求的适用性在主回复生成时判断。冷却记录的是提示机会，实际是否婉拒及措辞由模型结合主提示词决定。

## 安装

要求 Python 3.12+、AstrBot `>=4.29.4,<5`，使用 AstrBot 内置的模型 Provider SDK，额外依赖为零。

在 AstrBot 插件管理中通过仓库地址安装。

```text
https://github.com/1972124398/astrbot_plugin_short_term_mood
```

也可以在 AstrBot 根目录运行以下命令，然后在插件管理中重新扫描或重启 AstrBot。

```shell
git clone https://github.com/1972124398/astrbot_plugin_short_term_mood data/plugins/astrbot_plugin_short_term_mood
```

## 配置窗口

安装或更新后，在 **AstrBot WebUI → 插件 → 短期共享情绪 → 配置** 打开原生配置窗口。仓库根目录的 `_conf_schema.json` 为该窗口提供中文名称、说明、滑块和模型选择器。修改后点击窗口中的保存按钮，配置按 AstrBot 的插件配置流程生效。

| 配置项 | 默认值 | 用途 |
| --- | --- | --- |
| 启用共享短期情绪 | 开启 | 控制插件是否参与对话 |
| 情绪评估模型 Provider ID | 空，跟随会话 | 从已配置的 Provider 中选择后台模型 |
| 评估图片或表情 | 开启 | 向后台模型附带当前请求前两张图片 |
| 后台检测超时 | 15 秒 | 单次检测最长等待 |
| 检测失败重试间隔 | 30 秒 | 失败后暂停提交检测的时长 |
| 后台待检测消息上限 | 16 条 | 限制待处理队列 |
| 检测结果最长有效时间 | 120 秒 | 淘汰过期的消息与结果 |
| 持续对话时保持情绪 | 开启 | 活跃对话中暂停自然恢复 |
| 停止互动后的空闲时长 | 300 秒 | 超过后进入自然恢复 |
| 情绪强度半衰期 | 300 秒 | 自然恢复时强度减半速度 |
| 最长自然恢复时间 | 1200 秒 | 每种情绪恢复为平稳的累计期限 |
| 情绪敏感度 | 1.0 | 调节刺激的影响幅度 |
| 情绪性婉拒 | 开启 | 控制婉拒提示 |
| 婉拒强度阈值 | 0.65 | 触发抽样所需主导负面情绪强度 |
| 婉拒基础概率 | 0.3 | 与主导强度相乘得到提示概率 |
| 婉拒冷却 | 180 秒 | 两次提示机会的最短间隔 |
| 人格表达缓存期限 | 604800 秒 | 默认七天，到期后台重新生成 |
| 命令前缀 | `/`、`!` | 跳过对应命令的情绪处理 |

每条被处理的普通对话会额外产生一次后台模型调用，首次生成人格表达消耗更多输出 token。前台无需等待它完成，但使用同一个模型服务时仍共享服务端并发和额度。可在窗口中选用独立的检测 Provider。默认图片评估开启，需要评估模型支持图片。

检测失败、超时或输出无效时，当前心境按时间继续维持或恢复，等待配置的重试间隔后再检测新消息。关闭 `enabled` 可暂停整个插件，关闭 `enable_refusal` 可保留情绪表达并停止情绪性婉拒。

## 命令

| 命令 | 权限 | 效果 |
| --- | --- | --- |
| `/mood` | 所有人 | 查看智能体当前共享心境 |
| `/mood_reset` | 管理员 | 将全部会话共享的心境恢复平稳 |
| `/mood_set anger 0.8` | 管理员 | 设置共享情绪以调试，也可使用中文情绪名 |
| `/mood_refresh` | 管理员 | 清除人格情绪表达缓存，下轮重新生成 |

`mood_set` 接受 `joy`、`affection`、`sadness`、`anger`、`anxiety`、`fatigue`、`curiosity`，强度范围 0.04 到 1。设置会替换全部现有情绪，随后按时间恢复。

## 插件兼容

LLM 请求钩子优先级为 `-100`，在本机检查的记忆注入 `40`、默认钩子 `0` 和微信表情提示 `-50` 之后运行。兼容设计通过追加临时内容实现，原请求中的工具集合、图片、音频、用户输入、历史上下文和系统提示均交给现有流程管理。情绪评估使用 `Context.llm_generate()` 直接调用 Provider，因此不会递归进入对话钩子。评估调用使用自己的提示和输入，工具执行仍由主对话负责。

| 已检查的插件 | 版本 | 集成方式及范围 |
| --- | --- | --- |
| Codex Bridge | 1.2.0 | 保留已有工具授权与工具集合，`/codex` 等命令按前缀跳过 |
| 微信原生表情转图片 | 0.2.2 | 读取已转换图片，后置追加情绪临时内容 |
| Angel Memory | 3.1.0 | 在记忆注入后追加情绪，不调用记忆写入接口 |
| Reply Merge | 1.5.0 | 在合并请求之后评估，使用合并后的当前输入 |
| WeChat Native | 0.3.21 | 保留微信工具权限、PDF 内容和现有消息处理 |
| Proactive Chat | 1.3.0-beta.2 | 已检查其主动消息流程会派发标准 LLM 请求钩子，正常主动聊天会使用共享情绪 |

以上版本来自开发环境的源码接口检查，具体验证记录见下方。未来插件若覆盖整个内容列表，或自定义 Runner 绕过 `on_llm_request`，需要在对应集成点适配。其他插件可在事件中设置 `event.set_extra("short_term_mood_skip", True)`，让特定后台请求跳过情绪处理。

临时情绪提示会从 AstrBot 持久化的对话内容中排除。实际生成的回复仍可能被记忆插件观察并保存，长期记忆策略由记忆插件自己的配置决定。

## 数据与开发

运行数据位于 `data/plugin_data/astrbot_plugin_short_term_mood/mood.sqlite3`，存储共享情绪、互动与恢复计时、拒答标记和人格表达缓存。评估输入包含主提示词、最近对话和当前内容，会发送给所选的模型服务。待检测的输入快照在内存队列中保留，重启时清空。日志仅记录失败类型。

在仓库根目录运行核心回归验证。

```shell
python -m unittest discover -s tests -v
```

在能导入 AstrBot SDK 的 Python 环境中，同一命令还会运行真实 `ProviderRequest` 和 `TextPart` 的钩子集成验证。

在 AstrBot 4.29.4 SDK 环境通过 29 项回归验证，覆盖后台慢模型和超时期间的前台响应、跨会话联动、并发更新、队列淘汰、过期结果、重置后的晚到结果、重载取消、原生配置读取与保存、旧配置迁移、持续对话保持以及空闲恢复。GitHub Actions 分别运行 Python 3.11～3.13 的核心测试和 AstrBot 4.29.4 SDK 集成测试。

0.2.0 在独立测试状态下使用部署环境的 `deepseek-v4.1-flash`，验证赞赏、攻击、道歉会在后台更新情绪并生成八份人格表达提示。三次前台钩子额外耗时分别约 0.36、0.25、0.20 毫秒，相应后台检测耗时约 4.10、1.21、1.44 秒。这里测量的是插件钩子自身的耗时，实际聊天仍有模型生成与消息处理耗时。
