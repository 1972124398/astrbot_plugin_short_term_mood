# AstrBot 短期共享情绪

让智能体拥有一份跨私聊、群聊和人格联动的短期心境。一个会话中的赞赏、亲近、冲突或安慰，会影响它接下来在其他会话里的语气、耐心、主动性和对话意愿。

角色可以开心地多聊几句，生气时说出不满、反问或争辩，委屈时有保留，亲近时逗趣或撒娇，疲惫时想休息，也可以直接表达不愿意继续。表达方式由人格、当前心境和眼前的互动共同决定。

0.4.0 默认采用“随性自然”的日常聊天气质。角色可以接梗、轻怼、假装嫌弃、嘴硬着接话，也可以只回一小句感叹或半句心软的话。情绪会参与平时的礼貌、热情和接话意愿，让它有兴致时多聊一点，有小脾气时也能显露出来。

## 对话效果

0.3.0 使用真实模型进行连续五轮模拟朋友聊天，经过亲近、受攻击、继续被轻视、收到道歉和认真倾听，得到了以下回复片段。

| 互动 | 实际回复片段 |
| --- | --- |
| 忙完仍先来找它聊天 | “忙了一天还先来找我，这话挺受用的。” |
| 突然说它烦、没用 | “这翻脸速度我服。” |
| 认真承认刚才说话伤人 | “刚才那几句确实挺扎人的。” |
| 继续认真听它表达感受 | “你能这么讲我气消大半，工作上的事愿意说说吗？” |

这些片段来自模拟人格的真实生成。角色说话时有自己的感受，收到道歉后先松动，再随着互动逐步缓和。后台同时记录情绪强度、抽象的心境余韵和当前更自然的互动倾向。

支持开心、亲近、失落、生气、不安、疲惫、好奇、害羞、得意、委屈十种情绪，以及平稳状态。情绪可以混合，例如亲近与害羞并存，生气里带着委屈，接受道歉后仍有余气。每轮取最强的三种作为主要表达依据。

主提示词决定这个角色怎样表达。内敛的人格可以简短、冷淡或避开话题，活泼的人格可以嘴硬、开玩笑或主动亲近。配置窗口中的“情绪表达鲜明程度”和“补充情绪表达偏好”可以进一步调整口吻。

0.4.0 又进行了七轮连续日常聊天。被叫“小笨蛋”后它接了一句“反正你也没聪明到哪去”，后台仍以开心、害羞和亲近为主。被冷落后出现委屈和失落，随后在被哄时回“就是正好有点想喝”，状态逐步回暖。提示还会鼓励在连续嘴硬之后换一种自然表达，例如坦率承认高兴、直接答应或随口接话。

## 工作方式

1. 当前请求准备完成后，前台立即读取共享心境、情绪余韵、互动倾向和人格表达，以临时 `TextPart(...).mark_as_temp()` 加到 `extra_user_content_parts`。当前消息里的赞赏、挑衅、玩笑或关心，也可以在这一轮即时引起表达上的反应。
2. 同时保存当前主提示词、最近六条文字上下文、当前输入和图片引用的快照，放入后台检测队列。前台钩子没有网络等待，也无需等待后台的模型调用或数据库写入。
3. 单个后台任务按队列顺序评估本轮对智能体的刺激。每种情绪增量最多为 ±0.35，再乘敏感度，最终强度限制在 0 到 1。置信度低于 0.6 时按零刺激处理。
4. 首次遇到某份主提示词时，后台同一次调用会生成平稳和十种情绪各自的表达微调提示，并概括本轮后的情绪余韵和互动倾向。结果写入共享内存，从后续回复开始生效。首次生成完成前使用通用的角色表达提示。

所有会话共享同一个情绪状态，数据库保存状态以支持重启恢复。不同人格会用各自的措辞表达这份心境。数据库持久化在后台线程串行进行，前台使用内存中的状态。后台返回的结果会影响后续回复，一次已经开始生成的回复使用它开始时的情绪快照。

后台队列默认最多保留 16 个待处理请求，满时淘汰最早的待处理项。从入队到检测完成最长有效时间默认 120 秒，过期结果会丢弃。手动设置或重置情绪、清理表达缓存时，正在检测的旧结果和待处理项都会失效。卸载或重载会取消检测任务并保存当前状态。

后台保留最近五次抽象心境变化，例如“被夸后高兴 → 害羞着嘴硬 → 被冷落后别扭 → 得到关心后心软”。后续生成能沿着这段过程接话，复杂心境可以同时参与表达，例如嘴上嫌弃却愿意陪着、开心又不好意思、想靠近又有些委屈。恢复平稳后，这段短期轨迹也会清空。

评估输入保留完整主提示词，历史每条最多取末尾 800 字符，当前输入最多取末尾 10000 字符。主动聊天读取共享心境，主动发言内部指令产生的情绪增量固定为零。已缓存人格表达时，主动聊天直接复用缓存。

主提示词通常通过 AstrBot 的 `_trace_persona_id` 和人格管理器读取。WebChat 默认人格使用 AstrBot 的默认主提示词。第三方 Runner 未提供人格标识时，使用本次请求的 `system_prompt` 作为生成依据。

## 自动恢复

默认开启“持续对话时保持情绪”。所有真实对话共享活动计时，相邻互动不超过 300 秒时暂停情绪的自然衰减和恢复期限累计。安慰、冲突、赞赏等新互动仍能在后台改变情绪，持续聊天中也能从生气转为平静或开心。

“情绪余韵与惯性”默认 0.35，已有的强烈情绪在被安抚或转变时会保留一部分余韵，值越高，缓和的过程越慢。后台还会结合语境判断道歉是否认真、玩笑是否被接受，以及角色此刻更想靠近、说清不满、安静一会儿还是继续聊。

最后一次真实互动后，超过配置的空闲时长就进入自然恢复。默认每 300 秒强度减半，累计自然恢复 1200 秒后归于平稳。强度低于 0.04 时也会归于平稳。明显同类刺激重置该情绪的恢复累计。主动聊天和 `/mood` 等命令会读取情绪，活动计时由真实对话推进。

关闭“持续对话时保持情绪”后，会按实际经过时间持续恢复。离线时间计入恢复，重启后接着计算。读取状态时根据时间计算自然恢复，无消息时无需额外定时任务。升级时会读取 0.1.0 的已有状态，配置中已有的数值也会保留。

## 自主表达与拒绝

默认允许角色依据感受表达愿望和边界。它可以直接说“不想聊这个”“这话让我不舒服”“我还没消气”，也可以选择继续回答、追问、争辩、抱怨或转移话题。开心、好奇和亲近也会影响它是否更热情、更主动、想多聊一会儿。

表达由主提示词与当前语境决定。概率抽样、拒答阈值、拒答冷却和连续次数限制已移除。窗口中的“允许自主表达不愿意或拒绝”控制是否允许直接拒绝，关闭后仍能表达自己的情绪和偏好。角色自身的身份、事实判断与工具权限继续服从主提示词和 AstrBot 的既有流程。

## 安装

要求 Python 3.12+、AstrBot `>=4.29.4,<5`，使用 AstrBot 内置的模型 Provider SDK，额外依赖为零。

在 AstrBot 插件管理中通过仓库地址安装，安装完成后会自动加载插件并提供配置入口。更新时使用插件卡片的更新、重载功能。

```text
https://github.com/1972124398/astrbot_plugin_short_term_mood
```

也可以在 AstrBot 根目录运行以下命令，然后在插件管理中重新扫描并加载本插件。

```shell
git clone https://github.com/1972124398/astrbot_plugin_short_term_mood data/plugins/astrbot_plugin_short_term_mood
```

插件支持单独重载。安装、加载和重载时，运行数据写入 `data/plugin_data/astrbot_plugin_short_term_mood`，模型使用 AstrBot 中已配置的 Provider。

### Windows 原生微信运行环境

使用 Windows 原生微信服务的环境，如果在重启后出现 `database family must be private and stable`，并伴随原生微信 API 返回 HTTP 500，可检查微信服务数据库及其 `-wal`、`-shm` 文件是否属于服务运行账户。某些启动令牌会把 SQLite 新建的临时文件归属设为 Administrators，导致微信服务自己的文件归属检查失败。该环境问题也可能在其他重启或数据库临时文件重建时出现。

处理应在微信服务停止后，按其运行账户恢复相关文件归属，并修正微信服务启动进程的默认文件所有者。情绪插件的数据库为独立的 `mood.sqlite3`。插件的安装包包含情绪功能、配置窗口和测试代码，微信服务启动器由部署环境单独管理。

## 配置窗口

安装或更新后，在 **AstrBot WebUI → 插件 → 短期共享情绪 → 配置** 打开原生配置窗口。仓库根目录的 `_conf_schema.json` 为该窗口提供中文名称、说明、滑块和模型选择器。修改后点击窗口中的保存按钮，配置按 AstrBot 的插件配置流程生效。

| 配置项 | 默认值 | 用途 |
| --- | --- | --- |
| 启用共享短期情绪 | 开启 | 控制插件是否参与对话 |
| 情绪评估模型 Provider ID | 空，跟随会话 | 从已配置的 Provider 中选择后台模型 |
| 评估图片或表情 | 开启 | 向后台模型附带当前请求前两张图片 |
| 后台检测超时 | 30 秒 | 单次检测最长等待 |
| 检测失败重试间隔 | 30 秒 | 失败后暂停提交检测的时长 |
| 后台待检测消息上限 | 16 条 | 限制待处理队列 |
| 检测结果最长有效时间 | 120 秒 | 淘汰过期的消息与结果 |
| 持续对话时保持情绪 | 开启 | 活跃对话中暂停自然恢复 |
| 停止互动后的空闲时长 | 300 秒 | 超过后进入自然恢复 |
| 情绪强度半衰期 | 300 秒 | 自然恢复时强度减半速度 |
| 最长自然恢复时间 | 1200 秒 | 每种情绪恢复为平稳的累计期限 |
| 情绪敏感度 | 1.0 | 调节刺激的影响幅度 |
| 允许自主表达不愿意或拒绝 | 开启 | 允许角色结合当前感受直接拒绝或表达边界 |
| 情绪表达鲜明程度 | 1.0 | 较低更含蓄，较高表现更明显 |
| 让情绪充分参与聊天表达 | 开启 | 用固定的日常相处说明，让心境影响平时的礼貌、热情、耐心和接话意愿 |
| 日常聊天气质 | 随性自然 | 可选随性自然、活泼外露、含蓄细腻 |
| 玩心与接梗意愿 | 0.6 | 调节关系允许时的接梗、打趣、轻怼和嘴硬 |
| 情绪余韵与惯性 | 0.35 | 调节已有强烈心境被改变时的缓和速度 |
| 对当前消息即时表达情绪 | 开启 | 当前刺激可立即在说话中表现，后台负责持续心境 |
| 补充情绪表达偏好 | 空 | 如“生气时直说，亲近时多逗趣，少写动作描写” |
| 人格表达缓存期限 | 604800 秒 | 默认七天，到期后台重新生成 |
| 命令前缀 | `/`、`!` | 跳过对应命令的情绪处理 |

每条被处理的普通对话会额外产生一次后台模型调用，首次生成人格表达消耗更多输出 token。前台无需等待它完成，但使用同一个模型服务时仍共享服务端并发和额度。可在窗口中选用独立的检测 Provider。默认图片评估开启，需要评估模型支持图片。

检测失败、超时或输出无效时，当前心境按时间继续维持或恢复，等待配置的重试间隔后再检测新消息。关闭 `enabled` 可暂停整个插件，关闭 `enable_refusal` 可保留情绪表达并停止直接拒绝提示。

升级到 0.3.0 时会保留已有情绪、恢复时间、模型和开关设置。旧的 `refusal_threshold`、`refusal_probability` 和 `refusal_cooldown_seconds` 停止使用。人格表达缓存会在首次后台检测时更新为十种情绪与平稳状态，修改补充表达偏好后也会自动重新生成。

## 命令

| 命令 | 权限 | 效果 |
| --- | --- | --- |
| `/mood` | 所有人 | 查看共享心境、当前情绪余韵和互动倾向 |
| `/mood_reset` | 管理员 | 将全部会话共享的心境恢复平稳 |
| `/mood_set anger 0.8` | 管理员 | 设置共享情绪以调试，也可使用中文情绪名 |
| `/mood_refresh` | 管理员 | 清除人格情绪表达缓存，下轮重新生成 |

`mood_set` 接受 `joy`、`affection`、`sadness`、`anger`、`anxiety`、`fatigue`、`curiosity`、`embarrassment`、`pride`、`grievance`，也支持中文名称，强度范围 0.04 到 1。设置会替换全部现有情绪，随后按时间恢复。

## 插件兼容

LLM 请求钩子优先级为 `-100`，在本机检查的记忆注入 `40`、默认钩子 `0` 和微信表情提示 `-50` 之后运行。动态心境以临时内容追加，原请求中的工具集合、图片、音频、用户输入和历史上下文由现有流程管理。

“让情绪充分参与聊天表达”默认开启，会在已有系统提示尾部追加一段固定的日常相处说明，每轮最多一份。该说明支持心境改变平时的语气、热情、耐心与接话意愿，角色身份、关系和实际工具权限沿用主提示词。动态情绪数值与短期轨迹仍放在临时内容中。可以在配置窗口关闭该选项。

情绪评估使用 `Context.llm_generate()` 直接调用 Provider，因此不会递归进入对话钩子。评估调用使用自己的提示和输入，工具执行仍由主对话负责。

| 已检查的插件 | 版本 | 集成方式及范围 |
| --- | --- | --- |
| Codex Bridge | 1.2.0 | 保留已有工具授权与工具集合，`/codex` 等命令按前缀跳过 |
| 微信原生表情转图片 | 0.2.2 | 读取已转换图片，后置追加情绪临时内容 |
| Angel Memory | 3.1.0 | 在记忆注入后追加情绪，不调用记忆写入接口 |
| Reply Merge | 1.5.0 | 在合并请求之后评估，使用合并后的当前输入 |
| WeChat Native | 0.3.21 | 保留微信工具权限、PDF 内容和现有消息处理 |
| Proactive Chat | 1.3.0-beta.2 | 已检查其主动消息流程会派发标准 LLM 请求钩子，正常主动聊天会使用共享情绪 |

以上版本来自开发环境的源码接口检查，具体验证记录见下方。未来插件若覆盖整个内容列表，或自定义 Runner 绕过 `on_llm_request`，需要在对应集成点适配。其他插件可在事件中设置 `event.set_extra("short_term_mood_skip", True)`，让特定后台请求跳过情绪处理。

临时情绪提示会从 AstrBot 持久化的对话内容中排除。实际生成的回复仍可能被记忆插件观察并保存，长期记忆策略由记忆插件自己的配置决定。

## 数据与开发

运行数据位于 `data/plugin_data/astrbot_plugin_short_term_mood/mood.sqlite3`，存储共享情绪、互动与恢复计时、最近五次抽象心境、互动倾向和人格表达缓存。评估输入包含主提示词、最近对话和当前内容，会发送给所选的模型服务。待检测的输入快照在内存队列中保留，重启时清空。日志仅记录失败类型。

在仓库根目录运行核心回归验证。

```shell
python -m unittest discover -s tests -v
```

在能导入 AstrBot SDK 的 Python 环境中，同一命令还会运行真实 `ProviderRequest` 和 `TextPart` 的钩子集成验证。

在 AstrBot 4.29.4 SDK 环境验证日常聊天气质、短期心境轨迹、当前消息即时反应、连续回合的自主表达、情绪余韵、后台慢模型期间的前台响应、跨会话联动、原生配置、旧配置迁移、持续对话保持以及空闲恢复。安装回归还会在新进程与独立运行目录中使用 AstrBot 的真实核心初始化、插件加载和热重载流程，核对配置窗口 schema、数据库访问范围及其他插件文件保持完整。GitHub Actions 分别运行 Python 3.11～3.13 的核心测试和 AstrBot 4.29.4 SDK 集成测试。

0.2.0 在独立测试状态下使用部署环境的 `deepseek-v4.1-flash`，验证赞赏、攻击、道歉会在后台更新情绪并生成八份人格表达提示。三次前台钩子额外耗时分别约 0.36、0.25、0.20 毫秒，相应后台检测耗时约 4.10、1.21、1.44 秒。这里测量的是插件钩子自身的耗时，实际聊天仍有模型生成与消息处理耗时。

0.3.0 进一步运行连续五轮完整回复，观察到亲近、委屈、生气、接受道歉但仍有余气、认真倾听后的缓和。实际生成片段见文首，五轮前台钩子耗时约 0.09～0.20 毫秒。
