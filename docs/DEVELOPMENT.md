## 前台读取，后台决策

前台钩子只抓取请求快照、读取内存中的共享心境并加入临时文字参考，然后放入后台队列。它不选择心情、不执行情绪恢复、不处理久别候选，也不等待情绪模型、数据库锁或数据库写入。原有系统提示保持原样，不再追加情绪系统框架；评估格式、候选列表、时间偏好与切换说明只发送给后台模型。

前台参考包含当前抽象心境、互动倾向、情绪摘要和有限长度的人格表达。人格表达正文预算为 420 字，避免情绪目录扩展后把所有表现说明堆进聊天上下文。表达自由由主模型保留，具体人物与事件只使用当前会话可见内容。读取快照后已经开始生成的回复不被后台结果改写。

人格的身份、语气、关系边界与职责优先于表达偏好。每条表现参考按 `情绪强度 × expression_strength` 标注轻微（小于 0.3）、明显（0.3 至小于 0.7）或强烈（0.7 起），只帮助主模型理解表达分寸，不改变后台保存的心境。所有正强度情绪仍保留在摘要中，420 字预算包含表现前的情绪与分寸标签。`banter_level` 同时进入前台参考，0 不额外指定玩心，其他值提供较低、适中或较高的接梗意愿，始终服从人格和眼前语境。

主模型可以直接接住本轮道歉、澄清、关心或认真求助，保留余气或自然回暖，无需等待下一次后台评估；这是回复提示，不在前台写入心境。跨会话只共享抽象感受，不能推定当前用户是责怪对象或亲密对象。人格表达缓存也只能保存该人格可复用的表现，不应固化某次互动中的人物关系与称呼；表达契约更新后使用新的缓存键。

后台单 worker 顺序评估新互动，模型输出完整 `next_mood`，宿主校验后直接保存，不按敏感度或惯性二次计算、不执行固定混合搭配或切换路线。缺少的键表示模型决定放下，空对象表示平稳，微弱余韵也可保留。低置信度、失败或过期结果保留原状态。旧 `deltas` 仍接受 ±0.35 的增量，不再二次缩放。

后台保留最近五次抽象心境轨迹，余韵与互动倾向由模型自由描述。所有会话共享同一份心境，不同人格保留各自表达方式，跨会话不携带具体责怪对象、事实、关系或过错。

## 久别与可选恢复

真实聊天及游戏的到达时间随快照入队，在后台更新共享活动计时。全局默认停聊 6 小时后，后台模型收到 `return_context`，包含间隔、候选与轻重偏好，自主决定怎样继续。前台不知道候选或选择过程，当前回复沿用此前快照，新心境在后台完成后用于后续回复。

默认关闭 `natural_recovery_enabled`，读取状态与经过时间本身都不会自动切换心情。明确开启旧机制后，仅后台 worker 计算空闲、半衰期与恢复期限。主动发言、内部报告、浏览见闻及查询命令不会为真实互动计时续期。主动发言只读取共享心境，不把内部生成指令当作新刺激。

## 性能与持久化

评估输入保留人格、最近六条真实对话和当前内容，历史每条末尾最多 800 字、当前输入末尾最多 10000 字。后台同一次调用每次最多补齐 8 条人格表达，部分结果合并缓存并持久化，重启后继续补齐，不增加单独的表达生成请求。

默认队列最多保留 16 条待处理快照，满时淘汰最旧的待处理项。默认单次超时 30 秒、快照最长有效时间 120 秒、失败重试间隔 30 秒。慢模型不会阻塞前台，但共用模型服务时仍可能共享并发和额度，可配置独立的评估 Provider。

SQLite 写入在后台线程串行完成，状态保存在 `data/plugin_data/astrbot_plugin_short_term_mood/mood.sqlite3`。重置、手动设置或清缓存会使旧任务失效；卸载取消模型任务后保存状态。配置与其他插件目录不由情绪处理修改。

## 验证

```shell
python -m unittest discover -s tests -v
```

核心测试覆盖完整模型决策、旧格式、全部情绪、微弱余韵、别名、时间感与持久化。AstrBot SDK 测试覆盖前台只读、原始系统提示不变、无评估协议注入、慢模型下前台继续、不可变请求快照、队列和超时隔离，以及全新安装与热重载。

GitHub Actions 在 Python 3.11～3.13 运行核心测试，并在 AstrBot 4.29.4 环境运行 SDK 集成与安装回归。
